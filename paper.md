# Summary
MUSE (Multi-block Utility for Safe & Explainable Learning) is an open-source Python package for building machine learning models on block-structured tabular biomedical datasets, with a strong focus on interpretability and model documentation. MUSE enables researchers to integrate multiple data types (e.g. clinical measurements, multi-omics features, imaging radiomics) by organizing features into named blocks (modalities) and training a combined model. The package leverages the popular scikit-learn library for model training [@pedregosa2011scikitlearn], supporting classifiers such as random forests, gradient boosting machines, logistic regression, and shallow neural networks. To ensure the models are explainable, MUSE provides both global and local explanations using SHAP (SHapley Additive exPlanations [@Lundberg2017]) and permutation feature importance. Importantly, MUSE can aggregate feature importance at the block level, highlighting which data modalities contribute most to predictions. Additionally, the package automatically generates model cards [@mitchell2019model] – concise reports summarizing the model’s intended use, performance, and limitations – to promote safe and transparent deployment of biomedical AI models. The API is designed to be clean and intuitive, working seamlessly with pandas DataFrames [@reback2020pandas] and Jupyter notebooks for interactive model development.

# Statement of need
Modern biomedical research often involves heterogeneous data sources (for example, combining patient clinical data with genomic profiles or medical imaging features). Integrating such multi-modal or multi-omics data can improve predictive performance, but it poses challenges: researchers must carefully join different feature blocks and ensure that machine learning models remain interpretable and safe for clinical use. While scikit-learn [@pedregosa2011scikitlearn] provides a robust foundation for training classifiers on tabular data, it does not natively support grouping features by modality or producing detailed model documentation. Likewise, existing explainability libraries such as SHAP [@Lundberg2017] offer powerful tools for interpreting models, but using them typically requires custom coding and domain knowledge to aggregate results meaningfully across feature groups. 
MUSE addresses these gaps by offering an integrated framework tailored to biomedical block-structured data. It streamlines the workflow of training a model on multiple feature blocks and obtaining easy-to-understand explanations at both feature and block levels. This is particularly important in healthcare and biomedical AI, where regulations and best practices call for transparency, risk assessment, and documentation of models (e.g., via model reporting cards [@mitchell2019model]). By automating explainability and documentation, MUSE lowers the barrier for researchers and clinicians to develop trustworthy machine learning models that can be audited and safely deployed. No other single tool, to our knowledge, provides this combination of multi-block data handling, model-agnostic learning, and integrated explainable output geared towards regulatory compliance.

# Implementation and architecture
MUSE is implemented in Python and built on a modular architecture that wraps around any estimator following the scikit-learn API. At its core is a MultiBlockClassifier class (the primary interface for users), which manages the training and evaluation of a chosen classifier along with the metadata about feature blocks. Users provide the input data as a dictionary of pandas DataFrames or arrays, where each entry corresponds to one named block of features (for example, {"clinical": X_clinical, "omics": X_omics} for clinical and omics feature sets). Internally, the MultiBlockClassifier concatenates these blocks to form a single design matrix for model fitting, while retaining the block boundaries for downstream analysis. The class uses the scikit-learn estimator’s fit and predict_proba methods under the hood, ensuring compatibility with a wide range of classifiers (any classifier that implements the standard scikit-learn interface can be plugged in).

After model training, MUSE’s architecture collects information for explainability and reporting. For global interpretability, it computes feature importance using SHAP values: by default, it applies TreeExplainer or KernelExplainer from the SHAP library [@Lundberg2017] (chosen automatically based on the model type) on a background sample of the training data. The absolute SHAP values are averaged to quantify each feature’s overall impact on model output. These feature importances are then grouped by block: MUSE sums the contributions of features belonging to the same block, providing a high-level view of which data modalities are most influential. Additionally, the package can compute permutation feature importance as an optional model-agnostic check, though SHAP is the primary method due to its consistency and local interpretability. For local explanations (individual predictions), MUSE offers a method to obtain per-sample SHAP value breakdowns, indicating how each feature (and each block in aggregate) pushes the prediction for a given instance.

Another key component of the architecture is the model card generator. MUSE automatically assembles a structured model report following emerging best practices for AI transparency [@mitchell2019model]. This includes: metadata about the model (algorithm type, training data description), intended use and limitations, dataset details (e.g., name, size, feature blocks and their dimensions), performance metrics on evaluation data, and information about the computing environment for reproducibility. The model card is output as a human-readable text (for example, as Markdown or JSON that can be converted to PDF), so that developers can easily include it in documentation or supplemental material. The generation of this report is integrated into the model training pipeline – as soon as evaluation is done, the necessary stats and provenance (random seeds, library versions) are recorded. The design philosophy here is to embed good practices (like documenting risks and biases) into the software, thus encouraging users to consider these aspects without extra effort.

Throughout the implementation, emphasis is placed on a simple API. The MultiBlockClassifier exposes methods such as fit(), evaluate(), explain_global(), explain_local(), and generate_model_card(). These are high-level operations that internally orchestrate lower-level calls to scikit-learn and SHAP, as well as pandas for data manipulation. By abstracting away the boilerplate code, MUSE allows users to focus on interpreting results rather than writing custom glue code. The package is lightweight (built on widely used dependencies like scikit-learn, pandas [@reback2020pandas], numpy, and shap) and is suitable for interactive use in Jupyter notebooks as well as for scripting in larger pipelines.

# Example Usage 
MUSE is designed to be straightforward to use for data scientists familiar with pandas and scikit-learn. The following snippet illustrates a typical workflow using MUSE on a hypothetical multi-block dataset:
```python
from muse import MultiBlockClassifier
from sklearn.ensemble import RandomForestClassifier

# Prepare data blocks (e.g., clinical and omics DataFrames) and labels
blocks_train = {"clinical": X_clinical_train, "omics": X_omics_train}
blocks_test  = {"clinical": X_clinical_test,  "omics": X_omics_test}

# Initialize a MultiBlockClassifier with a Random Forest model
model = MultiBlockClassifier(estimator=RandomForestClassifier(n_estimators=100, class_weight="balanced"))

# Train the model
model.fit(blocks_train, y_train)

# Evaluate on test data
metrics = model.evaluate(blocks_test, y_test)
print("Test metrics:", metrics)  # e.g., accuracy, ROC AUC, etc.

# Generate global explanations (SHAP feature importances)
feature_importance, block_importance = model.explain_global(blocks_train)

# Produce a model card report
model_card_text = model.generate_model_card()
print(model_card_text)
```
In this example, X_clinical_train and X_omics_train could be pandas DataFrames holding clinical features and omics features respectively (with samples as rows). The MultiBlockClassifier is initialized with a RandomForestClassifier from scikit-learn as the underlying model – but it could just as easily be a logistic regression or gradient boosting classifier, since MUSE will call the same standard methods (fit, predict_proba) on it. After fitting the model on the training set, we evaluate it on a test set using evaluate(), which returns a dictionary of common metrics (accuracy, ROC AUC, F1-score, average precision, etc.). The explain_global() call computes SHAP values using the training data as background: it returns a DataFrame of feature-level importance (each feature’s mean |SHAP value|) and a summary of block-level importance. In this case, for example, one might find that the omics block contributes a larger share of the predictive power than the clinical block, or vice versa, depending on the problem. Finally, generate_model_card() produces a Markdown-formatted report of the model. This report would include sections like Model Overview (noting that we used a Random Forest, intended for a certain prediction task), Data (describing the dataset and feature blocks), Performance (listing the metrics from evaluate()), Explainability (highlighting which blocks were most important), and Limitations (with placeholders or user-provided notes about potential biases, dataset size, etc.). Users can save or edit this model card as needed.

Several detailed example notebooks are provided with MUSE to demonstrate its usage. These include a tutorial on the Wisconsin Diagnostic Breast Cancer (WDBC) dataset, an open UCI dataset where features describing cell nuclei are divided into blocks of mean, standard error, and “worst” (maximum) values for each cell measurement. Using MUSE on WDBC, a Random Forest model achieves high accuracy (~97%) and AUC (~0.99) on the task of classifying tumors as benign or malignant, and the block-level SHAP analysis reveals that the standard error block of features had the highest importance in the model’s predictions. Another example uses the CBIS-DDSM breast mammography dataset [@Lee2017] – specifically a curated set of radiomic features (designated CBIS-DDSM-R) extracted from mammogram images. In this case, MUSE is used to combine a small set of patient clinical features with a larger set of imaging-derived features for classifying breast lesions. The resulting model’s performance (around 79% accuracy and 0.86 ROC AUC on a test set) and the generated explanations show that the radiomic descriptors (e.g., characteristics of the mass shape and texture) are far more influential than basic clinical data in predicting malignancy. A third example notebook demonstrates MUSE on an institutional WAW-TACE dataset, which contains clinical variables and CT radiomics features for patients with hepatocellular carcinoma undergoing Transarterial Chemoembolization (TACE) therapy. This scenario exemplifies MUSE’s ability to handle a very high-dimensional feature space (over 3,300 radiomic features alongside ~40 clinical features): the model card produced for this case noted a modest predictive performance (reflecting the challenge of the task and limited sample size), but critically it documented the dominance of the radiomics_block in the model’s decision-making. Such insights can guide domain experts to understand which data sources are driving predictions, and whether the model might be over-relying on one modality.

Through these examples, users can learn how to apply MUSE to their own multi-modal biomedical datasets. The package’s documentation and notebooks illustrate how to incorporate custom feature preprocessing if needed, how to adjust SHAP computation for large feature sets (e.g., using max_background parameter to subsample the background data for efficiency), and how to enrich the model card with additional context (such as writing a brief Intended Use statement or listing any ethical considerations). By following the provided examples, practitioners can quickly adapt the framework to new problems in biomedicine, ensuring they get not only strong predictive models but also the accompanying explanations and safety checks.

# Performance / evaluation

We evaluate MUSE’s capabilities on multiple real-world datasets to illustrate its performance and usefulness:
1. WDBC (Breast Cancer): Using the WDBC dataset (569 samples, 30 features in 3 blocks of 10 each), MUSE reproduces state-of-the-art performance for tumor classification (e.g., 97.4% test accuracy with a Random Forest). The global SHAP analysis correctly identifies known important features (such as worst radius and worst texture of cell nuclei) and shows that the “standard error” block of features had the highest aggregate importance for the model’s predictions. The auto-generated model card for this experiment includes clear warnings about the dataset’s limitations (single-center data, small sample size) and suggestions for improvements (such as using cross-validation and external validation), which were populated from MUSE’s default template and can be edited by the user.
2. CBIS-DDSM Radiomics: In experiments on the CBIS-DDSM-R dataset [@Lee2017], which provides curated radiomic features for breast mammography cases, MUSE was used to integrate a clinical_block (patient age and other metadata) with a descriptor_block of 44 radiomic features per lesion. The trained gradient boosting classifier reached ~79% accuracy (F1 ~0.75) in distinguishing malignant from benign lesions, comparable to results reported in the literature for similar feature-based models. MUSE’s block-level explanations revealed that the radiomic descriptor block contributed about 3 times more to the model’s output than the clinical block, aligning with intuition that detailed image features carry more predictive signal for this task. The model card automatically documented the feature dimensionality of each block and the model’s performance metrics, aiding reproducibility. It also highlighted the need for external validation and noted the class imbalance as a risk (information that a practitioner might otherwise overlook to report).
3. WAW-TACE (HCC outcome prediction): We applied MUSE to a challenging proprietary dataset of 233 liver cancer patients (HCC) undergoing TACE therapy, where each patient had 45 clinical features and thousands of radiomic features extracted from CT scans. MUSE can seamlessly train a classifier on this high-dimensional multi-block data by utilizing a dimensionality-reduction-friendly algorithm (e.g., a tree-based model that can handle many features). In our test with a Random Forest, the model achieved moderate success (for instance, an F1-score of 0.85 for predicting 6-month survival, albeit with lower AUC ~0.59 due to the difficulty of the task). Crucially, MUSE’s explainability functions showed that the radiomics_block dominated the predictions – accounting for over 70% of the total feature importance – while the clinical_block had relatively small contributions. This outcome was automatically summarized in the model card’s Explainability section, alerting users that the model relies predominantly on imaging features. Such transparency is valuable for model developers: if the model’s behavior is driven by one modality, they might consider whether that modality has biases or if the other data sources are underutilized (perhaps due to quality or quantity issues). In this way, MUSE’s evaluation on the WAW-TACE data demonstrates its utility not only in delivering a model but also in diagnosing the model’s reliance on different data streams, which is essential for safe deployment in a clinical setting.

Overall, these use cases confirm that MUSE’s performance is on par with standard machine learning workflows (since it uses well-established algorithms from scikit-learn) while dramatically improving the usability of the results via automated explanations and reporting. The overhead introduced by computing SHAP values is manageable for datasets of these sizes (and can be tuned by subsampling), and the clarity gained in understanding model behavior is a significant advantage. For each example, the final outputs include a complete model card, which can be shared with collaborators, included in supplementary material of a publication, or used as documentation for regulatory review. By consolidating model training, explanation, and documentation, MUSE enables a more rigorous evaluation of predictive models in biomedical research.
